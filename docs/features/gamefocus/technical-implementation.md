## Technical Implementation

### Architecture Overview

```
               ┌───────────────────────────────────────────────┐
               │    Top Display (0): FocusTopLauncherActivity  │
               │   • FocusTopLauncherScreen (2:3 Poster Pager) │
               │   • FocusLibraryScreen (Condensed Grid & Tabs)│
               │   • GameFocusPairAppDialog (5-Column Modal)   │
               │   • FocusImageCache (LruCache + Icon Disk PNG)│
               │   • AppPaletteExtractor (Palette + Disk Cache)│
               │   • ExpandableActionsMenu (Subdued D-Pad UI)  │
               │   • GameFocusEditGameOverlay (Y Button Editor)│
               │   • GameFocusAccessibilityService (A11y Event)│
               └──────────────────────┬────────────────────────┘
                                      │ launches apps via setLaunchDisplayId(0) & setLaunchDisplayId(4)
                                      ▼
               ┌───────────────────────────────────────────────┐
               │         Primary App / Game Execution          │
               └──────────────────────┬────────────────────────┘

               ┌───────────────────────────────────────────────┐
               │     Bottom Display (4): MainActivity          │
               │   • Standard Megingiard Controls & Managers   │
               │   • Brought to front on Home by GameFocus     │
               └──────────────────────┴────────────────────────┘
```

- **Standalone App Modules:** Configured in `gamefocus/ui/build.gradle.kts` (`:gamefocus:ui`, standalone Android application `com.stormpanda.megingiard.gamefocus`) and `gamefocus/domain/build.gradle.kts` (`:gamefocus:domain`).
- **GameFocusDefaultLauncherManager:** Singleton in `:gamefocus:domain` (`GameFocusDefaultLauncherManager.kt`) verifying default home launcher status via `PackageManager.resolveActivity` with `MATCH_DEFAULT_ONLY`. Resolves target companion packages (`com.stormpanda.megingiard` or `.debug`) and dispatches launch intents targeting the secondary bottom display (`DisplayDetector.findSecondaryDisplay(context)`) with `FLAG_ACTIVITY_NEW_TASK or FLAG_ACTIVITY_RESET_TASK_IF_NEEDED` to preserve companion state.
- **GameFocusSessionTracker:** Singleton in `:gamefocus:domain` (`GameFocusSessionTracker.kt`) tracking active top and bottom applications (`lastTopApp`, `lastBottomApp`). Records launches initiated from Game Focus (`recordTopLaunch`, `recordBottomLaunch`) and window changes reported by the accessibility service (`recordWindowChanged`), restoring previous sessions via `restorePreviousSession(context)` targeting Display 0 and Display 4 with `FLAG_ACTIVITY_NEW_TASK or FLAG_ACTIVITY_RESET_TASK_IF_NEEDED`.
- **GameFocusAccessibilityService:** Optional `AccessibilityService` in `:gamefocus:ui` (`GameFocusAccessibilityService.kt`) listening to `TYPE_WINDOW_STATE_CHANGED` events to passively track foreground apps per display (`displayId == 0` for top screen, `displayId == secondaryDisplayId` for bottom screen) while filtering out system UI, Thor/Odin system overlays (`com.odin.*`), Google Play services, canonical launchers via `SystemRoleClassifier`, Game Focus, Megingiard Companion, and packages lacking launch intents. Preserves active ROM session state in `GameFocusSessionTracker` across emulator window updates.
- **GameFocusPairManager:** Singleton in `:gamefocus:domain` (`GameFocusPairManager.kt`) managing package pairing mappings (`Map<String, String>` where key = top screen package/ROM ID and value = bottom screen companion package) with atomic JSON persistence to `filesDir/gamefocus_app_pairs.json` via AndroidX `AtomicFile`. Exposes read-only `StateFlow<Map<String, String>>`.
- **GameFocusGalleryManager:** Singleton in `:gamefocus:domain` (`GameFocusGalleryManager.kt`) owning `GalleryConfig` (`collections`, `order`, `hidden`; models and pure helpers `validateCollectionName`, `collectionCategoryId`, and `GalleryOrdering.applyOrder` / `visibleIds` / `canHide` live in `GalleryConfig.kt`). Exposes a read-only `StateFlow<GalleryConfig>`. Mutations (`createCollection`, `renameCollection`, `deleteCollection`, `setCollectionMembership`, `setGalleryHidden`, `setGalleryOrder`) run under a state lock behind a `@Volatile isConfigLoaded` load-once guard and persist the latest in-memory snapshot asynchronously (`persistScope` + `persistLock`) to `filesDir/gamefocus_galleries.json` via `AtomicFile`. `setGalleryHidden` refuses to hide the last visible gallery. In `:gamefocus:ui`, `GameFocusCategory.buildOrderedGalleries` / `visibleGalleries` map the config plus ROM folders to the category roll; `GameFocusCategory.CustomCollection` compares by `id` only so renames and membership changes never reset the selected gallery, and collection pager states read their page count through `rememberUpdatedState`.
- **GameFocusManageGalleriesOverlay:** Primary overlay in `:gamefocus:ui` (`GameFocusManageGalleriesOverlay.kt`) hosted by `FocusTopLauncherScreen` while `FocusTopLauncherViewModel.isManageGalleriesOpen` is true (opened from the gallery / Library Y menus via shared `buildGalleryMenuActions` / `buildLibraryMenuActions` builders, with Manage Galleries always last). Three `ManageGalleriesPage`s (Visibility, Order, Collections) call `GameFocusGalleryManager.setGalleryHidden` / `setGalleryOrder` / `createCollection` / `renameCollection` / `deleteCollection` directly; pure helpers `canToggleGalleryVisibility`, `collectionMemberCount`, `collectionNameErrorResId`, `galleryIcon`, `galleryTitle` live in the same file. The collection detail view uses the scaffold's `isCustomBackActive` / `onCustomBack`; the activity back callback closes only the overlay. Key / joystick routing is shared with the Edit Game overlay via `isPrimaryOverlayOpen()`. The Order page reuses `GamepadReorderDeck`, which lives in `:shared:ui` (`GamepadReorderDeck.kt`) and is also used by the Companion MacroPad editor.
- **GameFocusEditGameOverlay:** Primary overlay in `:gamefocus:ui` (`GameFocusEditGameOverlay.kt`) providing four categories (`GAME INFO`, `GALLERY ARTWORK`, `LIBRARY ICON`, `COLLECTIONS`). The Collections deck (`CollectionsMembershipDeckContent`) observes `GameFocusGalleryManager.config` and toggles game membership immediately with asynchronous persistence via `setCollectionMembership`, displaying live catalog entry counts and providing a direct shortcut to `GameFocusManageGalleriesOverlay` when no custom collections exist yet.
- **ContentProvider Inter-Process Theme Syncing & Client State Dispatch:** Megingiard Companion (`:companion:ui`) hosts `MegingiardThemeProvider` (`content://com.stormpanda.megingiard.provider/theme`). Game Focus queries this URI on launch via `MegingiardThemeClient` and attaches a `ContentObserver` for real-time theme and accent color synchronization across process boundaries. Client state updates (`MegingiardSettingsClient.updateClientState`) are non-blocking: each call enqueues a full state snapshot into a conflated `Channel` drained by a single consumer coroutine on `Dispatchers.IO` (`SupervisorJob` scope). This keeps synchronous ContentResolver IPC off the Compose UI thread during rapid D-pad or joystick carousel navigation while guaranteeing strict ordering (a late hover update can never overwrite the `isActive = false` sent from `onStop`) and latest-wins conflation (superseded pending snapshots are dropped). If Megingiard is absent, Game Focus safely defaults to `ThemeMode.DARK`.
- **InstalledAppsManager:** Singleton in `:shared:catalog` querying `PackageManager` for native apps, combined with ROM items loaded via `RomManager`. Intercepts launch requests in `launchAppOnDisplay` to delegate ROM launches to the registry instead of launching package intents directly.
- **EmulatorDetectionFunnel & Detectors:** Central router singleton in `:shared:session` (`EmulatorDetectionFunnel.kt`) routing foreground process changes to active detectors (`RetroArchDetector`, `GameNativeDetector` for PC/Steam emulators in `PcEmulators` including GameNative and DroidDeck, `Pcsx2AndroidDetector`, `YuzuDetector` for Switch emulators including Citron, Eden, Sudachi, Suyu, and Yuzu, and `PpssppDetector` for standalone PPSSPP emulators), parsing configuration, process trees, and log files to track running ROM sessions (`ActiveGameSession`) and trigger automatic companion profile switching.
- **RomLauncher & Registry:** Registry singleton in `:shared:catalog` (`RomLauncherRegistry.kt`) housing the extensible `RomLauncher` API, mapping emulator IDs to specific implementations in `:gamefocus:domain`: `RetroArchLauncher` (resolving absolute paths and firing target activities with `ROM` and `LIBRETRO` parameters), `GameNativeLauncher` (resolving the assigned or first installed `PcEmulators` package—GameNative or DroidDeck—and launching PC games via `app_id` extra parameters), and `SwitchLauncher` (launching Nintendo Switch games via `TECH_DISCOVERED` intent with component target).
- **SwitchRomClassifier & Recursive RomManager:** `RomManager` in `:shared:catalog` collects DocumentFile trees recursively up to `MAX_SCAN_DEPTH = 3` to discover games stored in dedicated subdirectories. For Nintendo Switch libraries (`systemId == "switch"`), `SwitchRomClassifier` analyzes Title IDs (`000` base, `800` update, `001-FFE` DLC), extensions (`.xci`/`.xcz`), and bracketed tags to index base games exclusively while discarding updates and DLC packages.
- **LibraryTab:** Sealed class in `:gamefocus:domain` (`LibraryTab.kt`) representing library categories (`GAMES`, `APPS`, and dynamic `RomSystem`), tab list construction (`LibraryTab.fromRomFolders`), tab wrap-around navigation (`next(tabs)` / `previous(tabs)`), and app filtering (`filterApps`).
- **FocusLibraryScreen:** Composable in `:gamefocus:ui` (`FocusLibraryScreen.kt`) rendering static tabs, condensed square rounded-corner grid layout with hidden app `visibility_off` badges, and a lower-left `ExpandableActionsMenu` for browsing, hiding/unhiding, editing, and launching installed apps. Highlighted focus bounds are drawn by an animated overlay layered above the grid; its outer accent glow uses `BlurMaskFilter.Blur.OUTER` (halo rendered only outside the card shape) plus a solid stroke band for the spread ring, so the focused card is never tinted and no `clipPath(..., ClipOp.Difference)` stencil clip is needed (avoiding GPU stencil fallbacks and CPU rasterization on Adreno RenderThreads).
- **LetterNavigationHelper:** Platform-free helper in `:gamefocus:domain` (`LetterNavigationHelper.kt`) providing starting letter extraction (`getStartingLetter`) and index calculation for forward (R1) and backward (L1) letter skipping across installed app lists with wrap-around support.
- **AppPaletteExtractor:** Utility object in `gamefocus/ui/src/main/java/com/stormpanda/megingiard/gamefocus/AppPaletteExtractor.kt` extracting the most vibrant primary and distinct secondary colors via AndroidX `Palette` (ranking swatches by saturation & lightness score, enforcing distinct HSV separation, and generating hue-shifted vibrant fallbacks) with `LruCache` and `SharedPreferences` persistence (`gamefocus_palettes_v2`).
- **FocusImageCache:** In-memory `LruCache` in `FocusTopLauncherScreen.kt` for poster cover bitmaps, converted icon/logo PNGs (`cacheDir/gamefocus_icons/`, `cacheDir/gamefocus_logos/`), and custom library icons and logos (`cacheDir/gamefocus_library_icons/`). Scraped game logos and icons are automatically sampled and downsized to a maximum dimension of 256px (`decodeSampledIconBitmap`) to prevent multi-megapixel master artwork from exhausting native heap or stalling GPU composition during grid animations. If an icon file cannot be decoded natively and is a Windows `.ico` container, embedded PNG streams are extracted via `IcoImageExtractor`. Decoding (`decodeSampledIconBitmap`) is side-effect free. Negative lookups for missing or failed icons are tracked in-memory (`missingLibraryIconKeys`) to prevent redundant disk I/O, coroutine dispatch loops, and PackageManager exception overhead during rapid scrolling. Custom library icons are exposed through `rememberLibraryIconBitmap`, querying the cache or loading from disk asynchronously.
- **LibraryIconRef & Custom Icon Persistence:** Pure data class `LibraryIconRef(id, type)` in `:shared:core` (`LibraryIconRef.kt`) representing a selected SteamGridDB icon or logo. Custom icon selections for native apps and ROMs are persisted to `filesDir/gamefocus_library_icon_ids.json` using atomic file writes (`AtomicFile`). `InstalledAppsManager` manages loading, saving, downloading, applying (`applyCustomLibraryIcon` with automatic downsampling to max 256px), and reverting (`revertToDefaultLibraryIcon`) custom icons, automatically syncing in-memory `InstalledAppInfo` (`libraryIconPath`, `libraryIconImageId`, `libraryIconType`, `libraryIconLastModified`) across catalog scans.
- **Manifest Integration & Home/Back Handling:** `gamefocus/ui/src/main/AndroidManifest.xml` declares `FocusTopLauncherActivity` as a `singleTask` system launcher with `android.intent.category.HOME` and `android.intent.category.DEFAULT` intent filters. Overrides `onNewIntent` and intercepts `KEYCODE_HOME` / `KEYCODE_BUTTON_MODE` in `onKeyDown` to reset view state (`resetToGallery()`) and trigger `GameFocusDefaultLauncherManager.handleHomeNavigation(this)`. Intercepts `isDismissKey` (`KEYCODE_BACK`, `BUTTON_B`, `KEYCODE_ESCAPE`) and registers `OnBackPressedCallback` to dismiss sub-views first and restore previous dual-screen app sessions when at the root gallery via `GameFocusSessionTracker.restorePreviousSession(this)`. Consumes `isDismissKey` in `onKeyUp` to prevent unconsumed Back key releases from being intercepted by the system WindowManager (`persistBackUp`) and moving restored activities to the background.
- **GameFocusPreferences:** Singleton in `:gamefocus:domain` (`GameFocusPreferences.kt`) managing user preferences via `SharedPreferences` (`gamefocus_preferences`), persisting `button_prompts_visible` state toggled by the R3 stick click across both Gallery and Library views.
- **GameFocusHaptics:** Singleton utility in `:gamefocus:ui` (`GameFocusHaptics.kt`) delivering zero-config, low-latency tactile feedback for controller navigation. Caches the system `Vibrator` via `applicationContext` to prevent Activity leaks, queries hardware composition support (`vibrator.areAllPrimitivesSupported`) for `PRIMITIVE_CLICK`, and scales to `0.45f` for micro-ticks and `1.0f` for firm boundary clicks (avoiding 0ms dummy primitives 8 and 7 on Qualcomm HALs), falling back to pre-calibrated micro-pulses (`8ms` / `12ms`) on hardware without primitive composition. All vibrations are dispatched with `VibrationAttributes.USAGE_TOUCH` to honor system touch-feedback preferences.
